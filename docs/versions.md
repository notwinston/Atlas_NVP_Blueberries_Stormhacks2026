## The Forge's TripoSG set-up, pinned for the Station (4 Oct 2026)

Resolved with `uv pip compile` for Python 3.11 on Windows (`x86_64-pc-windows-msvc`) against PyPI and the cu128 PyTorch
index, the lock file, `requirements-triposg.txt` and `requirements-gpu.txt` together. Every pin has a Windows wheel
except `antlr4-python3-runtime`, which is pure Python. **None of it has been installed on Windows or with CUDA.** Install
order: `station/forge/README.md`, "First run on the Station".

| Component | Pinned | Where | Status |
|---|---|---|---|

| CUDA Toolkit, for `diso` | 12.8, with `CUDA_HOME` set | The README's prerequisites | Not installed on the Station |

What really ran on the build Mac, on 4 October 2026, in a throw-away Python 3.11.16 environment (deleted): the lock file,
`requirements-triposg.txt`, PyTorch 2.7.1 for the processor and `rembg[cpu]==2.0.69` were installed, and the TripoSG package
imported through the adapter's own import with `diso` replaced by a stub. It printed numpy 2.4.6, torch 2.7.1, diffusers
0.33.1, transformers 4.49.0, scikit-image 0.25.2, scipy 1.15.2, huggingface-hub 0.30.2, peft 0.15.2. No weights were
downloaded and nothing was generated.

## Not yet verified

- iOS version on phone A and phone B, and the tracking drift test (C.2).
- apple/unityplugins Core + CoreHaptics: not added yet (built from source, C.3).
- Station PC: .NET SDK 8, Python 3.11, PyTorch 2.7.1 cu128, CUDA Toolkit 12.8, `diso` 0.1.4, rembg, the TripoSG commit and the Forge's lock file. The lists were resolved for Windows and never installed there.
- Unity Editor at the same patch on the other three machines.
- The Phase 1 code of all four lanes (A, B, C and D) in the Unity Editor: it compiles against the 6000.3.25f1 assemblies and its engine-free tests pass under `tools/headless/verify.py`, but it has not been imported, rendered or run in Unity or on a phone. `docs/verification/UNITY_SIDE_BRIEF.md` is the check list.
- TripoSG on the RTX 5070: the Forge's adapter is written from the public repository's inference API and has never run; the tests use the procedural generator and a fake pipeline. On the build Mac the TripoSG package imported with `diso` replaced by a stub, and nothing was generated: no weights were downloaded. TripoSG's output frame, its time and memory per object, and whether `diso` builds and runs on the Station are unmeasured.
