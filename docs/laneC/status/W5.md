## Deviations and notes

1. `docs/laneC/P2_DESIGN.md` and the Shell foundation are not on `laneC/phase2` (the branch is Phase 1 only), so I followed the plan rows and the Build Graph chunk C3. `RoomsExhibit` does not derive from a shell base class; the integrator wires it to `ExhibitMenu` (P2-C08) and `PromptQueue` (P2-C09) through `Prompt` / `PromptChanged`, `Restart()` and `Core.Completed`.
2. `rooms.loop` is already logged by `PortalSpace` (`{room, laps}`, lane D contract row, lane A owner) at the crossing that finishes a lap. The exhibit therefore logs no event of its own, so the Station sees exactly one `rooms.loop` per lap. In a loop layout the room id equals the room number (room k+1 carries number k+1), so the event's `room` is the number shown on the sign. The exhibit's own record is `Core.LastLap` (start number, arrival number, turns walked).
3. A lap is counted at a doorway, as in lane A. With `rooms.count` 2, 4, 5, 6 that is exactly four right turns; with 3 the corners of the rooms carry it to six turns, so the lap prompt names the number of turns actually walked. The default is 6 rooms.
4. The plan's "WorldLint physical fit" is `RoomsFitLint` here. Lane B's `WorldLint` checks generated props against the room footprint, not portal layouts, so there is nothing to bind to it.
5. The IEquationSource for S5 is P2-A03 (lane A). The seam is `RoomsExhibitCore.FloorRatio`, `VirtualFloorVisited`, `FreeRectArea`.
6. Verify needed a third git-excluded shim, `shim/RoomModelBuilder.cs` into `ATLAS/Assets/Atlas/Scan/Build/` (baseline did not compile without it). Not committed. `gen_meta.py` also wrote `.meta` files for the shim sources; they are untracked and not committed.
7. The caption chip text (`RoomsText.Caption`) is the plan's wording; the chip itself is P2-C06. Prompt texts are my wording (the plan gives none).
