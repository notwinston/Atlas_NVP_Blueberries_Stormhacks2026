# Lane B placeholders for lanes A, C and D

> Integrating Lane B with the real lane A/C/D code? Start with [INTEGRATION_NOTES.md](INTEGRATION_NOTES.md).

Branch `laneB/placeholders` = `laneB/ph-A` + `laneB/ph-C` + `laneB/ph-D` (merged without conflicts) + `P1-B01`
(lane B's own kernel stubs: `Iso2`, `TileId`, `WalkerPose`, which `ISpaceModule` and `SpaceLab` need). Every placeholder
carries the header `// PLACEHOLDER (lane X, task): contract surface only; replaced by lane X's implementation` and is
replaced file-for-file by the owning lane's real file. Lane B code and tests call only the public members below and
write their own test doubles. Tags: [plan] fixed by the Master Plan (MP); [min] smallest choice, PH-n id.

## Repository and plan conflicts

- R1. `ISpaceModule` needs `Atlas.Link` from `Atlas.World`. Done here: `Atlas.World.asmdef` references Link and
  `WorldDependencyTests` allows `{Kernel, Link}`. Lane A must keep it.
- R2. The Spaces asmdefs reference no `Atlas.Link` yet. Lane B adds it to CurvedWalk, AlignedCells and SmallPlanet when those tasks start.
- R3. `Atlas.Safety` references `Atlas.World` (added by lane B on this branch, to match MP §6.2 "World (RoomModel types only)"); `Atlas.Scan` is still there although MP §6.2 does not list it. Lane C's call.
- R4. MP §6.2 has an `Atlas.App` assembly (`AtlasFrameLoop`, lane A); main has none.
- R5. App C.9 says `atlas/unity/Assets`; the repository uses `ATLAS/Assets`.
- R6. Spaces may not reference `Atlas.Scan`, so the Home rebuild output crosses through `IHomeShell` in `Atlas.World` and `SpaceLab.Home`.
- R7. Blades.Lung / Blades.FieldFit lack Unity.Mathematics/Burst/Collections and URP references; lane B adds them and announces it.
- R8. No lane owns C# readers for tree.json and sky.json; lane B writes them inside P2-B01 and P2-B10 (PH-30).
- R9. P2-B09 does not need Mesh4D (MP §10.2.8); only P4-B02 does.
- Merge note: lanes C and D placeholders are in `Atlas.World` / `Atlas.Link` and merged without conflicts (disjoint files). The
  kernel types `WalkerPose`, `TileId`, `Iso2` come from branch `P1-B01` (lane B), because `ISpaceModule` and `SpaceLab` use them.

## Swap-out rules for the owning lanes

- S1. Tests/PlaceholdersA, PlaceholdersC and PlaceholdersD are lane B self-tests of the placeholders. When an owner real
  code lands, delete that lane Tests/Placeholders<X> directory in the same commit: several tests assert placeholder-only
  behaviour that the real contracts do not have (a synchronous switch in `Placeholder_SpaceLab_StepOrder`, PH-4 says real
  switching is async; identity `SourceUV`; cameras created in OnEnable; fixture endpoints in `Placeholder_PoseLog_Lap5`),
  and would turn main red (MP §11.1: all tests run before every merge).
- S2. Placeholder-only helpers are `internal`: `GamepadActionSource`, `HomeRebuild.BudgetStandInHash`, the `PoseSample`
  constructor (PH-40). Atlas.Input `AssemblyInfo.cs` grants `InternalsVisibleTo` to the placeholder test assembly
  `Atlas.PlaceholdersC.Tests`; remove that line with the tests.
- S3. Lane B code uses only the public surface in the table above.
